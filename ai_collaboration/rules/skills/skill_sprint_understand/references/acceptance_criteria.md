# 验收标准规范

## 1. 验收标准的定义

验收标准（Acceptance Criteria）是对需求完成的明确定义，用于判断功能是否满足要求。

### 1.1 验收标准的作用

```mermaid
flowchart LR
    A[需求描述] --> B[验收标准]
    B --> C[测试用例]
    C --> D[验证结果]
    D --> E[验收确认]
```

### 1.2 验收标准的特征

- **明确性**：没有歧义，可以明确判断
- **可测试性**：可以通过测试验证
- **完整性**：覆盖正常和异常场景
- **独立性**：每条标准独立可验证

## 2. Given-When-Then 格式

### 2.1 格式说明

```gherkin
Given [前置条件/初始状态]
When [用户行为/触发动作]
Then [预期结果/系统响应]
```

### 2.2 示例

```gherkin
# 示例1：用户登录
Given 用户在登录页面
When 用户输入正确的用户名和密码并点击登录
Then 系统跳转到首页并显示用户信息

# 示例2：数据查询
Given 用户已登录且有查询权限
When 用户输入查询条件并点击搜索
Then 系统返回符合条件的列表数据
And 列表按时间倒序排列
And 支持分页显示

# 示例3：异常处理
Given 用户输入了错误的密码
When 用户点击登录
Then 系统显示"用户名或密码错误"提示
And 用户可以重新输入
```

## 3. 验收标准分类

### 3.1 功能性验收标准

| 类型 | 说明 | 示例 |
|------|------|------|
| **正向流程** | 正常操作的预期结果 | 登录成功跳转首页 |
| **逆向流程** | 异常操作的预期结果 | 密码错误提示信息 |
| **边界条件** | 边界值处理 | 分页最大值、输入长度限制 |
| **数据校验** | 数据格式验证 | 手机号格式、邮箱格式 |

### 3.2 非功能性验收标准

| 类型 | 说明 | 示例 |
|------|------|------|
| **性能要求** | 响应时间、吞吐量 | 页面加载<3秒，接口响应<500ms |
| **安全要求** | 权限、加密、审计 | 未登录不能访问，敏感数据加密 |
| **可用性要求** | 系统稳定性 | 99.9%可用性 |
| **兼容性要求** | 浏览器、设备支持 | Chrome/Firefox/Safari |

## 4. 验收标准编写模板

### 4.1 功能验收标准模板

```markdown
## 功能名称：{功能描述}

### 正常场景
1. Given [前置条件] When [操作] Then [结果]
2. Given [前置条件] When [操作] Then [结果]

### 异常场景
1. Given [前置条件] When [异常操作] Then [错误提示]
2. Given [前置条件] When [异常操作] Then [错误提示]

### 边界场景
1. Given [边界条件] When [操作] Then [处理结果]
2. Given [边界条件] When [操作] Then [处理结果]

### 非功能要求
- 性能：响应时间 < x秒
- 安全：权限控制要求
- 兼容：支持的浏览器/设备
```

### 4.2 接口验收标准模板

```markdown
## 接口名称：{接口描述}

### 请求参数校验
| 参数 | 类型 | 必填 | 校验规则 | 错误提示 |
|------|------|------|----------|----------|
| id | Long | 是 | 大于0 | ID无效 |
| name | String | 是 | 1-50字符 | 名称长度1-50字符 |

### 响应结果校验
| 场景 | 响应码 | 响应信息 | 数据 |
|------|--------|----------|------|
| 成功 | 200 | success | {...} |
| 参数错误 | 400 | 参数校验失败 | null |
| 未授权 | 401 | 未登录 | null |
```
