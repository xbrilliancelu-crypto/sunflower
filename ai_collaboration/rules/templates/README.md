# 设计方案模板与风险评估规范（templates/）

## 概述

本目录存放详细技术方案设计过程中所需遵循的模板文档和风险评估规范，是 AI 协作框架中方案设计阶段的核心参考资源。

## 目录结构

```
templates/
├── detail_solution_template.md  # 详细设计方案模板
├── dependency_analysis.md       # 变更风险评估规范
└── legacy_refactor_strategy.md  # 渐进式重构策略
```

## 文档说明

### 1. detail_solution_template.md - 详细设计方案模板

定义详细技术方案的标准结构和内容要求：

- **方案概述**：需求背景、技术目标、约束条件
- **模块拆分设计**：模块划分、依赖关系、职责边界
- **数据流模型定义**：核心数据结构、流转路径、存储方案
- **关键功能点分析**：技术选型、实现方案、性能考量
- **演进规划**：迭代计划、风险控制、回滚策略

**使用场景**：当需要进行某个需求或模块的详细设计方案分析时，参考本模板进行方案编写。

### 2. dependency_analysis.md - 变更风险评估规范

定义代码变更的风险评估方法和流程：

- **变更影响范围分析**：识别直接依赖和间接依赖
- **风险评估矩阵**：评估变更的风险等级
- **核心模块识别**：标记需要特别关注的核心模块
- **风险缓解措施**：制定变更前的预防策略

**使用场景**：在修改历史代码前，必须参考本规范进行风险评估。

### 3. legacy_refactor_strategy.md - 渐进式重构策略

定义历史代码的渐进式重构方法和原则：

- **重构原则**：最小侵入、渐进演进、可回滚
- **循环依赖处理**：识别和解决循环依赖的策略
- **分层重构方法**：从外向内、从下向上的重构路径
- **技术债务管理**：债务识别、优先级排序、逐步偿还

**使用场景**：发现循环依赖或需要进行大范围代码重构时，参考本策略执行。

## 使用指南

### 方案设计流程

```
1. 阅读 arch_solutions.md 了解架构要求
2. 参考本目录下的模板和规范
3. 编写详细设计方案（写入 docs/detail_solutions/）
4. 方案评审通过后进入任务拆解阶段
```

### 风险评估流程

```
1. 识别变更涉及的模块和文件
2. 参考 dependency_analysis.md 进行影响分析
3. 评估风险等级，制定缓解措施
4. 高风险变更需进行架构评审
```
